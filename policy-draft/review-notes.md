# OMNI 정책 문서 게시 전 검토 메모

작성일: 2026년 10월 19일 · 운영자 검토용

## 1. 수정 범위

첨부 원문, 이 세션에서 확인한 OMNI-Bot 코드 및 아래 공식 자료를 기준으로 개정안을 작성했습니다. 실제 배포 서버, 호스팅 계약, 메일 설정, 데이터 삭제 결과를 확인한 보안·법률 실사는 아닙니다. 법적 적합성이나 규제기관 승인을 보증하지 않습니다.

기존 문서는 별도 파일에 보존했고, 개정안은 미시행으로 표시했습니다. 운영자가 정하지 않은 시행일, 실명, 사업자 정보, 위탁 업체나 해외 수령국을 만들어 넣지 않았습니다.

## 2. 게시 전에 확정할 사항

| 사항 | 확인 또는 조치 |
| --- | --- |
| 약관 동의 | 처음 이용할 때 약관을 안내하고 명확한 동의를 받는 절차를 구현. 서버 관리자 동의를 모든 이용자 동의로 대체하지 않음 |
| 이메일 동의 | `/관리자 등록`에서 저장 전에 목적·항목·기간·거부권을 알리고 동의를 확인. 현재 코드의 저장 후 안내와 동의 간주 문구 보완 |
| 운영 주체 | Felnut의 법적 표시, 개인정보 보호책임자 또는 담당 조직 표시, 필요한 연락처 확정. 닉네임을 실명으로 단정하지 않음 |
| 위탁·국외 이전 | 실제 서버·백업 국가, 호스팅·메일 업체, Discord API 응답과 검색어 전달 흐름 확인. 해당 수령자·국가·시기·방법·목적·기간·법적 근거·거부 방법 기재 |
| 보유 기간 | 원문의 로그 30일 보장과 코드의 수정 시각 기준 파일 삭제를 일치시킬 것. 로그 회전·검색어 매핑·백업 폐기 주기 확정 |
| 삭제 요청 | user뿐 아니라 admin_contact, guild_school.registered_by, warning, dday, transfer_log, 진행 게임·미정산 베팅, 로그·백업·Discord 게시물을 함께 검토 |
| 처리 근거 | 제3자에 대한 경고 기록과 보안 기록 처리의 역할·근거 검토. 정당한 이익을 사용할 경우 목적·필요성·권리 침해 균형 기록 |
| 공지·시행 | 실제 공고일과 사전 안내 기간을 정한 뒤 시행일 확정. 중요한 변경은 일반 이용자가 접근할 수 있는 경로로 안내 |

## 3. 코드에서 확인한 차이

- `bot/events/messageCreate/baseballGuess.js`: 유효한 숫자 입력을 `game.history`에 추가하고 `saveGame` 호출. ‘메시지 내용은 저장하지 않는다’는 일괄 표현 수정.
- `bot/managers/maintenance.js`: 마지막 이용 후 365일, 송금 후 7일, 경고 365일, 디데이 날짜 경과 30일을 기준으로 시작 시 및 24시간마다 정리. 경계 시점에 즉시 삭제되는 구조는 아님.
- 같은 파일: `music/logs`의 `.log`·`.gz`를 마지막 수정 시각으로 삭제. 계속 기록되는 파일의 오래된 항목은 남을 수 있으며 표준 출력 등 다른 로그 저장소까지 자동 정리되는 것은 아님.
- `Database.js`: 학교 등록자 ID·시각, 급식 알림 채널·마지막 전송일 저장. 기존 방침의 항목 누락 보완.
- 경제 계정 미이용 삭제 루틴에는 관리자 이메일·학교 등록자·모든 서버 설정 삭제가 포함되어 있지 않음. ‘전체 이용 기록이 자동으로 모두 삭제’된다는 표현 사용 금지.
- `bot/commands/admin/admin_contact.js`: 이메일 등록 후 안내 및 `consented_at` 기록. 기록 필드 이름만으로 적법한 사전 동의를 입증할 수는 없음.
- `bot/managers/musicCache.js`: 검색어-결과 매핑을 파일에 저장. 음악 메타데이터에 Discord ID가 없더라도 검색어 자체에 개인정보가 포함될 수 있음.

## 4. 게시 절차

1. 위 사항을 확인하고 필요한 구현·운영 설정을 보완합니다.
2. privacy.md의 검토 안내를 실제 확정 정보로 대체합니다. 확인 문구를 지우기만 해서 해결되는 것은 아닙니다.
3. terms.md와 privacy.md의 공고일·시행일 및 문서 상태를 갱신합니다.
4. changelog.md에서 개정안을 시행 버전으로 이동하고 기존 문서의 적용 종료일을 기록합니다.
5. 기존 버전 파일 두 개도 함께 올립니다. 세 문서의 `.md` 링크는 저장소에서 동작하며 GitHub Pages에서의 연결은 배포 후 확인합니다.
